# Floating-island terrain revision

Updated: 2026-10-06. Status: functional review passed; visual acceptance pending. The goal remains active.

The active workshop now uses shared rounded contours over sparse 2D height data, rather than a 3D voxel volume. Fixed vertical cliff samples and local profiles preserve distant rocks after local edits. Exposed grass caps subtract higher regions, including holes. An immutable revision builds two chunks per frame, then publishes its meshes, instanced detail, support props and picking together. Newer input coalesces into the next snapshot, so sustained painting continues to publish terrain.

These captures drain ordinary incremental updates and do not force a full rebuild to mask stale geometry. Each edit starts from the composition layout. [Capture metadata](captures.json) records brush centers, radii and changed cells. PNGs remain local per repository policy; the capture script reproduces them.

The wider upper terrace, shifted ponds and falls, supported trees, cottage, fences, bench and lantern now follow the reference composition more closely. Existing CC0 Kenney source models and the refined cottage remain unchanged. The supporting cliff body now carries stronger world-anchored material facets and rounded cellular shoulders, with occasional embedded stone_largeA models rather than repeated vertical stacks. The geometry/material site field uses matching 2.2×1.8×2.2 dimensions; relief caches by exact warped position within each refresh. Extra shoulders fade out on narrow profiles, retaining the existing one-cell-strip shape. Broad profiles have reduced directional and vertical wave noise. The latest actual cliff close-up breaks up long diagonal folds into more distinct rock regions, while the latest shading divides each site with three oblique planes into smaller angular faces. Reduced vertical normal curvature and a narrower gray range soften horizontal bands. An initial quantized-normal variant created thin stretched patches; it was discarded. Final world-space face selection uses continuous body normals and remains anchored across chunks and edits. Embedded CC0 stones share a palette helper with the body, selected once from each transformed instance origin, and keep their existing physical flat normals. The matching material is applied after model merging. This is a shading improvement; the continuous physical shell and some elongated lower-wall patches still differ from the target’s rock volumes and ledges. Runtime canopies use 14 overlapping lobes above a taller, broader detailed-tree trunk, with a reduced ellipsoid blend (.48) and per-lobe tint. Existing forks are more visible. The retained low forks receive a runtime upward lift, with XZ coordinates, base vertices at Y≤.18 and topology preserved. This meets the raised crown without the extra low leaf clusters that hid the forks. A temporary actual-mesh ray-parity probe initially found two tips outside leaves; final fork lifting covers four sampled fork/stem endpoints. This checks the chosen points, not every branch segment or all view angles. Original GLB source files remain intact. Hanging foliage assembles flattened leaf sprays; shoreline stones use flatter stone_largeD parts with deterministic size and angle variation. Shorter grass and subtle lawn color facets calm the ground. The cottage has broader workshop proportions and warmer timber panels across both walls and gables. Its retained corrected-material names now separate plaster, timber and foundation stone from roof treatment, replacing the height-only/brightness classification. Object-space normals keep panel posts fixed when the view changes. The textured roof retains its source texture with a warmer runtime tint; no cottage geometry changed. Bench and lantern remain placeholders. No custom model-generation service or purchase was used. The built-in image-generation tool produced a cloud-only sky backdrop; its [source record and exact prompt](../../../source/skies/2026-10-05/cloud_backdrop_v01.json) accompany the runtime copy in `assets/terrain_editor/cloud_backdrop_v01.png`. The backdrop fills the fixed camera view and uses neutral cubemap lighting; terrain and props remain interactive 3D geometry.

Pond shallow-bank and floor-depth color derive from the same terrain snapshot. Its texture publishes alongside the completed mesh, keeping partial rebuilds from changing visible water early. This adds a shoreline appearance transition, not refraction or fluid simulation. Falling water uses finer moving polygonal veins (5.2×2.6 UV frequency) with varied line brightness, a lighter blue palette and reduced emission. The distortion depends entirely on advected flow coordinates, so the full pattern moves downward. Pixel-footprint smoothing replaces subpixel dotted highlights at distant views; the joined curtain geometry is unchanged. Independent review cleared the advection direction and shader correctness, but flagged excessive net brightness; the final glint strength was lowered from .86 to .55 and actual captures regenerated. The pattern remains visible and sheet-like; still images cannot establish temporal shimmer quality. Joined raised foam rings have interpolated smooth normals, a transparent edge and slight surface motion; chunk clipping preserves their opacity and normals. Independent review found no important remaining issue after the downward animation correction.

Visual differences remain: broad cliff areas are smoother than the target's broken rock volumes; tree crowns still show assembled rounded lobes, open lawns remain simpler, and shoreline stones repeat; falls still read as sheets with patterned veins and a modest splash; the cottage lacks finer timber bays and ornament; the detailed cloud backdrop contrasts with the simpler tree and cliff surfaces. This is a closer editable reconstruction, not an accepted reproduction. Fine custom-model changes remain subject to the user-operated asset workflow.

[Verification](verification.json).

Measured on Apple M4 Pro, Metal Forward+, 1280×720, shadows and SSAO enabled, vsync disabled: three 12-second runs after two-second warmups. Median frame time 9.201–9.424 ms; p95 18.393–18.574 ms; worst sampled frame 82.890 ms. Four edits per run became visible in 136.507–180.076 ms. Every frame is sampled independently through normal two-chunk update waits. [Measurements](performance.json). Default terrain has 595 cells; samples end at 593 after edits. Draw calls include shadow passes (496); static memory was about 58.1 MiB; video memory 206.9 MiB. The previous cottage pass measured median 5.433–6.488 ms and edits 119.081–151.499 ms. Current measured frame times are higher; this refinement is not a performance improvement. The trial that used the full body shader on embedded stones measured median 9.198–9.241 ms; moving them to the cheaper shader reduces algorithmic work but did not produce a measured frame-time improvement in these samples. Capture runs use fixed-step timing and UI counters are not benchmark evidence.

These short development-machine samples do not establish large-layout scaling, target laptop performance, or long-idle power/stability. Function, visual quality and performance acceptance remain separate.
