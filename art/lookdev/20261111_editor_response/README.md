# 编辑高度、草坪渐变与高分辨率预览

2026-11-11。唯一运行入口为 `scenes/terrain_editor.tscn`。本包图片均为 Godot 4.7.2 实际输出。审阅入口为 [compare.html](compare.html)。

## 整笔使用落笔处高度

- 工具栏恢复为六项地形操作，撤回上轮误加的“齐平”。
- 鼠标先拾取权威高度图的顶部。落笔后，所有地面笔刷沿同一示意平面工作，拖过其他台阶也保持起点高度。升降仍按既有半米步长执行。
- 扩张可从已有高台内部落笔取高，再拖出边缘。新地接续该高度。侧墙起笔保留其顶部归属，避免投影偏到另一层。
- 引泉、退水也以落笔处实际床面锁层。水面与装饰岩柱的形体分别参与原有水体显示和岩体编辑。
- 原生输入验证从 3.5m 高台落笔，示意圈为 3.56m，三格新地均为 3.5m。蓝图、提交两个阶段见 `review/upper_plane_*.png`。

## 草随淹水消隐，从邻草恢复

逐格记录视觉覆盖度。水到达对应床面后，草叶与草唇在约 0.65 秒内缩短、渐隐，地表同步露出湿泥石。空间插值使交界过渡连续，较高的干草冠保留自身高度判断。

退水后以相邻干草为源传播，每格完全恢复约需 0.85 秒，内部跟随邻格逐步展开。再次淹水会中断恢复。整个岛面都曾被淹且缺少草源时，选择外边界干燥 3 秒后重新播种，再向内传播。

动画只更新视觉覆盖度。水量继续由有限体积求解器负责。深坑可从高处相邻草坪恢复。

`review/flood.webp` 与 `regrow.webp` 为生产草时钟每次推进 0.05 秒的原生帧序列，1280×720。关键帧为 2560×1440。演示先以降地笔刷形成坑地，运行守恒水流 3 秒，再冻结物理水以单独观察草动画。恢复演示由现有退水工具清除局部水，视频中的池水减少来自该工具。动画循环末尾会重置到首帧。

## 4K 性能与清晰度取舍

默认流畅预览按帧耗时调节三维内部像素预算，范围为 1920×1080 至 2560×1440。4K 输出及界面保持原生，三维场景经过 FSR1 放大。2K 及以下窗口保持原生三维。卷菜单的“原生画质”可恢复全尺寸三维与原有 4×MSAA。

界面绘制改为显示状态变化时才刷新，进度弧按约 1/256 的变化触发重绘。本次采样 120 帧中界面重绘由 120 次降至 13 次。云层透明绘制范围也缩到其有效范围。

Apple M4 Pro 开发机，BASE_A 相机，生产编辑循环、悬停拾取和水流开启。预热 240 帧后测量 120 帧，关闭垂直同步，显式整帧绘制，采样期无截图写盘。

| 模式 | 三维内部 | 平均帧耗时 | 中位数 | 95 分位 |
| --- | --- | --- | --- | --- |
| 界面重绘优化前的流畅预览 | 1920×1080 | 33.80ms | 33.13ms | 36.34ms |
| 当前流畅预览 | 1920×1080 | 22.48ms | 17.73ms | 35.33ms |

运行耗时受水流推进和实际经过时间影响，两次采样结束的水量有差异。上表为运行状态，旧记录约 47ms 的原生 4K 测量属于冻结场景。GPU 计时不可用，这些数值均为整帧耗时。

当前仍有慢帧，原生 4K 运行仍明显偏慢。流畅预览的细草、远景边缘会更软，可在页面中对照两张同数据 4K 图。Windows 轻薄本和 MacBook Air 的约 60FPS 目标仍待实测。
