## 结果与取舍

- 编辑上限60FPS；F11静置壁纸上限30FPS，输入后立即恢复60并保持2秒；最小化暂停场景，仅5Hz轻量监控，恢复续行。失焦的可见壁纸继续动画。退出还原原Engine限帧；尊重已有更低上限。
- 材质、分辨率预算、MSAA、草/岩石数不主动削减。30FPS降低动画时间采样。动态分辨率清除帧率模式切换的旧样本、忽略最小化、达到限帧时每5秒小幅试探恢复原2K预算，保留原生画质开关。
- 水系统只在精确可见格集合改变时重建轮廓/三角化。法线保留原累计顺序和精度，共享位置只归一化一次。完全相同的床面/水深/水面/流量不重复发布GPU资源。被丢弃的worker结果不能成为缓存的已发布状态；reset等待worker后失效。草场贴图复用未变的边界归属，地形高度/格集合改变时重建。

## 实测

Godot4.7.2，Apple M4 Pro；不是Windows轻薄本或MacBook Air。所有进程串行采样，无截图写盘进入计时。

| 1280×720原生实时壁纸，关闭VSync | FPS | 进程CPU（按单核计） |
|---|---:|---:|
| 任务起点，无上限 | 91.05 | 45.09% |
| 优化后静置 | 30.00 | 34.11% |
| 优化后最小化、场景暂停 | 监控5Hz | 0.49% |

3秒预热、8秒采样，用ps的CPU累计时间差计算；不是温度、整机能耗或GPU利用率测量。最小化后恢复的场景继续处理、上限回到30，已实测。运行日志runtime_*.json。

原生4×MSAA、BASE_A、固定光照、每帧固定推进水1/60s、不限帧显式绘制：2K均值34.58→34.24ms，4K64.89→65.77ms。波动范围内持平，不能据此声称原生4K FPS提升；GPU侧仍偏慢。保留此前4K的动态1080p—2K内部3D预算。

固定100次.1秒水更新（含flush的完整CPU路径），preset0总时间3465→3265ms、preset1 13015→11808ms、无水preset2 629→317ms；单轮测量，约6%、9%、50%减少。无水发布101→1次，水量/外排量逐值相同。此工具的flush会主动同步，不等同生产10Hz的单个worker成本；不把最后一次0秒同步的solver字段误当真实求解耗时。checks/water_work_before.json及water_work_normals_final.json为最终对照；water_work_after/final为中间候选。
