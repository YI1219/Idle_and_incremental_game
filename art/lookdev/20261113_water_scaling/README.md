# 水更新结构优化 · 2026-11-13

用户批准借鉴连续数组、减少复制、限制更新范围。生产改动只有 `scripts/terrain_editor/water_flow.gd` 和 `water_renderer.gd`；新增 `tests/water_scaling_test.gd`。唯一场景、岩壁几何/材质/配色/光照、植被数量、时间步和流速系数不改。

## 已实现

- 保留权威稀疏地形与公开水状态字典。拓扑变更时建立索引与邻接，流量热循环使用Float64连续缓冲，只访问湿格及接收邻格，保留原单元/方向顺序与算法。
- 使用row-major整数索引原生排序，消除原型中每步GDScript比较函数造成的小岛回退。
- 仅在所有有效水头都非正时休眠；正水头即使因微量水/时间下溢而产生零通量也不休眠。无epsilon弃水或降低模拟频率。
- worker join后按作者输入版本/seed替换不可变地形快照，正常步复用；pending sync和地形revision拒绝旧结果。作者编辑、reset和seed失效均覆盖。
- 普通发布只写回变化水量；显式write/flush保留直接编辑核对和非法原始水量规范化。
- 干地底图按快照缓存，正常步只修改湿格及仍有outgoing的干涸供水格。仍需全幅图像复制/清空/纹理上传。

## CPU扩容实测

M4Pro、Godot4.7.2 headless，固定原水域，增加独立干地区域；623/2492/9968格是总地形格数，并非16倍可见物件或全场景扩容。ABBA各两次，所有最终水量/外排量精确相同。

|流水布局|100次纯求解：前→后|40次完整水更新：前→后|完整路径耗时减少|
|---|---:|---:|---:|
|1倍 /623格|874.81→833.34ms|807.38→720.24ms|10.8%|
|4倍 /2492格|1112.60→821.56ms|1334.13→788.82ms|40.9%|
|16倍 /9968格|2062.03→822.19ms|3397.72→1064.62ms|68.7%|

完整路径含worker排队/等待、求解、网格/贴图生成和主线程发布的墙钟耗时，非GPU帧耗时；初次配置不在该计时内。固定40次普通更新只建1份快照；作者编辑仍重建。稳定闭池固定40次更新：1倍4.92→.38ms、16倍69.90→.41ms，不据此声称整场景节能99%。原型回退记录保留在checks/probe_initial.json，最终见checks/probe.json与probe_summary.json。
