# 2026-11-12 FPS优化

[实际Godot前后对照](compare.html) · [最终验证](checks/final_validation.json)

用户授权从模型精度等方面继续提高FPS，允许整体观感小幅取舍。当前项目、唯一入口不变，原dirty work/岩壁形态/候选资产完整保留。未生成模型、未付费、未扩展玩法。

## 保留改动

- `grass_field.gd`：近景完整网格96面及中档LOD、原顶点/法线/颜色/UV均不变。最远LOD移除毫米级内部截面脊，单簇28→14面；保留7叶的左右外沿、根、尖、风与淹水动画。草密度与放置数据不变。
- `preview_quality.gd`：默认所有尺寸2×MSAA，方向阴影图集4096，2K及以下保持原生像素；原生开关恢复初始化MSAA（生产为4×）和8192阴影。保留原4K动态1080p—2K内部3D预算、UI原生和所有节能限帧。不改灯色/角度/曝光/阴影bias或岩石材质。
- `runtime_power.gd`：修复headless显示后端将虚拟Window.mode报告为MINIMIZED、从而停掉输入的前轮边界。真实窗口最小化仍暂停，恢复/30FPS壁纸逻辑保留。新测试先RED，再16项GREEN；控制29与runtime22恢复，最终全量回归通过。
- `capture_lookdev.gd`：正式原生采图明确关功耗监控并设native，避免新默认设置污染“4×MSAA原生”元数据；记录真实MSAA/scale、显式阴影图集尺寸，并把质量/功耗脚本加入源码hash。最终28帧在此版本重采。

## 先测开销再决定减什么

原生2K固定BASE_A、静态光照/相位，50次显式绘制：baseline约24.2—24.7ms；无草19.93，无装饰22.26，无云22.66，4096阴影22.52，2×MSAA21.62。去掉远山虽让提交的primitive计数从846489降至114899，耗时仅24.70→24.44ms，因此没有削减远山或改其形体。SSAO半尺寸收益小，没有采用；云/材质/光照也未改。

同一live scene的组合测试：2K约24.5→19.2ms，4K47.2→39.7ms。2K仅改远景草约24.9→23.0ms；4K远景草收益很小，主要收益来自阴影和MSAA。计数器对MultiMesh未必代表实例相乘的真实三角工作量，因此不把全景primitive差当作整场景减面比例。详见ablation.json与candidate_probe.json。

## 实际运行FPS

Apple M4 Pro / Godot4.7.2 / Metal Forward+。固定尺寸、UPDATE_ALWAYS的SubViewport正常渲染循环；生产editor真实光照及水流持续更新，固定BASE_A，每组3秒预热+8秒采样，关闭VSync与帧率上限，无截图I/O计入采样，图形进程串行运行。

| 相同渲染像素/场景 | 起点FPS | 优化后FPS | 起点/当前p95帧耗时 |
|---|---:|---:|---:|
| 原生2560×1440 | 41.08 | 51.67（+25.8%） | 27.00 / 22.06ms |
| 原生3840×2160 | 21.51 | 25.56（+18.8%） | 48.76 / 41.77ms |
| 3840×2160输出、固定1920×1080内部3D | 61.44 | 63.10 | 18.58 / 18.24ms |

4K固定流畅预算原本就2×MSAA，收益较小。8秒单轮运行不能证明所有镜头和长时负载；水演进按真实时间，结束simulated_seconds约11.0—11.1，未拿不同水状态作图片对照。固定状态的显式绘制AB/BA复采支持原生像素场景的提升。不是Windows轻薄本/MacBookAir实测，4K全像素仍达不到60FPS。壁纸实际仍按30FPS节能上限运行。

最初普通Window试验被macOS窗口尺寸/拉伸限制，实际texture为2289×1288，不能标为请求的2K/4K。`runtime_2k/4k/scaled4k_*.json`均已排除，仅保留诊断；最终只用`runtime_view_*.json`，其resolution与texture_size逐项相等。剔除说明见excluded_window_samples.json。

## 回退与范围

checks/*_before.gd.txt及*.patch是本轮精确差异；不用HEAD整体回退。project.godot、远山、纹理与模型资产不变。`原生画质`可即时恢复较高MSAA/阴影，草的近景精度原本就保留。只需重运行唯一场景加载。
