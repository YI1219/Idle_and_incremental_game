## Required when publishing a custom task later

For each task, write separately: asset use and size, links to four inspected independent front/left/right/back images, multi-view mode, topology and target polycount, texturing stage, export format, exact save directory and filenames. The four views generate one model together, not four models, and not collage input. Polycount and texture size follow asset use; do not generalize old cottage settings to every asset.

Generate the untextured model first and download GLB. Inspect silhouette, structure, doorway and other key places, and topology. User account feedback: same-parameter retries may be free; changing parameters may cost credits; generating textures is 10 credits and cannot be retried afterward. Finish form screening, then decide texturing or baking. Static props need no rig or animation.

New originals go in the task's specified `source` subdirectory, with textures or archives kept together. Do not overwrite old files or game runtime assets. Attach parameter screenshots or asset links when available; passwords are not needed. When actual parameters are unknown, do not write suggestions as facts.

For future explicitly selected 3D assets, the user leads model inspection/refinement; Codex supports agreed style and integration. Keep work in `work`, reports in `review`, and import to `assets` after acceptance.
